# This is the measured third-party import closure of
# `python -m backend.extraction_service` (T1a's brief), not the root
# `requirements.txt` -- that file targets the full voice+graph backend
# image and leaves most of this list unpinned (it relies on the
# torch/chatterbox install order in docker/backend/Dockerfile to pull them
# in transitively). Every module below IS actually imported at process
# start; verified 2026-09-26 by running the service's entry import
# (`import backend.extraction_service.app`) inside the worker container and
# reading `sys.modules`.
#
# Pin policy: where the repo root requirements.txt already pins a
# distribution with `==`, that pin is used here unchanged. Everything else
# is pinned to the version installed in this worker's container
# (`pip show <name>` / `pip list --format=freeze`, read 2026-09-26) -- the
# root requirements.txt itself leaves these unpinned or does not list them,
# so there is no in-repo exact pin to copy.
#

#   annotated_doc     -> annotated-doc      fastapi dependency (Annotated[..., Doc(...)])
#   annotated_types   -> annotated-types    pydantic dependency

# list because that list names modules `app.py`/`engine.py` import, and

#
# NEO4J/PANDAS/PYARROW/NUMPY removed 2026-09-26 (goal mist-two-loop v2-lazy-imports,
# MIS-171): these previously appeared solely as a side effect of two eager
# package `__init__` imports, never because any extraction-service code path
# called Neo4j or built a DataFrame:
#   1. `backend/knowledge/extraction/__init__.py` eagerly imported
#      `pipeline.py` (which imports `numpy` for embedding math and
#      `GraphStore`) -- running that `__init__` on ANY import of a
#      `backend.knowledge.extraction` submodule, even one `engine.py`/
#      `app.py` import directly by name (e.g. `internal_derivation`,
#      `ontology_extractor`, `preprocessor`), because importing a submodule
#      always runs its package `__init__` first.
#   2. `backend/knowledge/storage/__init__.py` eagerly imported `GraphStore`
#      and `Neo4jConnection`, the latter doing `from neo4j import Driver,
#      GraphDatabase`. neo4j's own `neo4j/_optional_deps/__init__.py` then
#      unconditionally imports `pandas` (installed in this repo as a
#      lancedb/sentence-transformers dependency, so the optional import
#      always succeeded), and pandas' own `pandas/compat/pyarrow.py` does an
#      unconditional `import pyarrow` as part of pandas's own init chain.
# Both `__init__` modules are now PEP 562 lazy (`__getattr__`): every name
# they previously imported eagerly is still importable by name, just no
# longer imported as a side effect of importing the package or any of its
# submodules. `backend/knowledge/extraction/internal_derivation.py`'s
# `GraphExecutor` import (a type-only annotation) moved under
# `TYPE_CHECKING` for the same reason -- it is the only other path into
# `backend.knowledge.storage` this service's import graph had.
# Re-measured 2026-09-26 the same way as above, after both changes: the
# closure no longer contains `neo4j`, `pandas`, `pyarrow`, `numpy`, `pytz`,
# `dateutil`, or `six`.
